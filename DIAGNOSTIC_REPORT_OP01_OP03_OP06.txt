PART 2: XAI ADVISORY INVESTIGATION (OP01, OP03, OP04, OP06)
-------------------------------------------------------------------------------
Symptom:
In prior test runs, queries under OP01 (Current Status) and OP03 (Fault Diagnosis) produced text with only temporal scopes and header information:
  "Diagnostic run for FS-17 (objective: OP01_CURRENT_STATUS): Temporal Scope: ..."
and emitted frames:
  ['status', 'visual', 'text_delta', 'done']
with the 'advisory' frame missing, whereas OP04 (Health Assessment) emitted:
  ['advisory', 'visual', 'text_delta', 'done']

Root Cause Analysis:
1. Manifests vs Prompts:
   - Grep: `grep -r "narrator" config/objectives/` returned NO matches. Manifests do not configure prompts.
   - Central router `app/llm/calls.py` routes prompt files:
       OP04 -> narrator_health_v1.txt
       OP05 -> narrator_early_warning_v1.txt
       OP14 -> narrator_history_v1.txt
       OP02 -> narrator_decline_rca_v1.txt
       OP06 -> narrator_procedure_v1.txt
       OP01 & OP03 -> narrator_v1.txt (default fallback)

2. Markdown Fence Stripping Defect in `app/llm/calls.py`:
   - `call_llm_chat` returned JSON enclosed in ```` ```json ... ``` ````.
   - The original `_strip_markdown_fence(content)` only stripped fences if `content.startswith("```")`. If there was any leading whitespace, newline, or conversational preamble, stripping failed.
   - `json.loads` threw `JSONDecodeError`, triggering a strict retry.
   - If the strict retry also failed or hit timeout, `calls.py` raised `AdvisoryOutputInvalid`.

3. Silent Drop in `runner.py` & `response_assembler.py`:
   - In `app/workflow/runner.py`:
       except Exception as e:
           logging.exception("synthesize_advisory failed: %s", e)
           advisory = None
   - In `app/synthesis/response_assembler.py`:
       if advisory:
           yield AdvisoryFrame(...)
   - When `advisory` was None, the assembler silently omitted the `AdvisoryFrame`, and `_format_advisory_text` omitted the Assessment and Recommendation sections, producing the hollow output observed.

4. LLM Timeout on CPU:
   - When large evidence blocks (1,300+ chars) were sent, Qwen2.5-Coder-3B took 60-90s on CPU. The previous default `LLM_TIMEOUT_SEC=30.0` caused timeouts.

Fix Implemented:
1. `app/llm/calls.py`:
   Updated `_strip_markdown_fence` to use robust regular expression extraction:
     `re.search(r"```(?:json)?\s*([\s\S]*?)\s*```", content)`
   with fallback to outermost `{ ... }` boundaries.
2. `agent_service/.env`:
   Set `LLM_TIMEOUT_SEC=180` to accommodate multi-step generation without client drop.
3. `run_kb_regression.py`:
   Fixed stream parser to inspect `delta` as well as `text` in `TextDeltaFrame`.
