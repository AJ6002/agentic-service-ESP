----------------------------------------------------------

Assessment text:
  "Production rate is stable with no abnormal decline detected. The production
   trend for FS-17 is DECLINING at a rate of 10.00 BPD/day."
Flag:

Contradiction:
  Sentence 1 says: "Production rate is stable with no abnormal decline detected."
  Sentence 2 says: "The production trend for FS-17 is DECLINING at a rate of 10.00 BPD/day."

2. CAUSAL CHAIN & FILE:LINE TRACE
---------------------------------

   In `agent_service/app/evidence/formatter.py` lines 225-227:
   `is_declining = pct_change > 5.0 and decline_rate_per_day > 0.0`
   `trend_str = "DECLINING" if is_declining else "STABLE"`
   For FS-17 in the queried 2-hour window, production was STABLE (`production_trend = "STABLE"`).
b. In LLM synthesis:
   The user query was leading: "Why has FS-17 production declined?"
   Despite Rule 14 in `narrator_decline_rca_v1.txt` ("DO NOT force an artificial
   decline narrative or invent fictitious decline rates"), the 3B LLM answered the
   question's presupposition and fabricated:
   "The production trend for FS-17 is DECLINING at a rate of 10.00 BPD/day."
   (The 10.00 was completely fabricated, which is why numeric provenance warned on it).
c. In `agent_service/app/synthesis/xai.py` lines 143-161:
   ```python
   trend_item = evidence.by_signal("production_trend")
   trend = str(trend_item.raw) if (trend_item and trend_item.raw) else "STABLE"
   if trend == "DECLINING":
       ...
   else:
       # Stable well: ensure assessment explicitly states stability and no fake decline is forced
       if "stable" not in advisory.assessment.lower() and "no decline" not in advisory.assessment.lower():
           advisory.assessment = "Production rate is stable with no abnormal decline detected. " + advisory.assessment
   ```
   Because `trend == "STABLE"`, it entered the `else:` branch.
   Because the LLM had hallucinated a decline and had NOT written "stable", the guard

   directly in front of the LLM's hallucinated text!

2. CAUSAL CHAIN & FILE:LINE TRACE
---------------------------------
a. In `agent_service/app/routing/router.py` lines 306-318 (and fallback lines 67-81):
   ```python
   # Ambiguous follow-up guard: "Why did that happen?" or "Explain that" in empty session -> CLARIFY
   if AMBIGUOUS_FOLLOWUP_PATTERNS.search(router_input.raw_message) or (
       FOLLOWUP_PATTERNS.search(router_input.raw_message) and not router_input.has_prior and router_input.turn_count <= 1
   ):
       decision.route = "WORKFLOW"
       decision.intent = "diagnose"
       decision.objective_id = "OP03_FAULT_DIAGNOSIS"
       decision.args = {"asset_id": router_input.asset_id}
       decision.confidence = 0.4
       decision.clarification_needed = True
       decision.clarify_reason = "CLARIFY"
       decision.clarify_slot = "followup_or_new" if router_input.has_prior else "asset_id"
       decision.clarify_options = ["Explain previous diagnosis", "Run new diagnosis on current telemetry"] if router_input.has_prior else ["FS-17", "FS-91", "FNW-01", "FWS-06"]
   ```
b. Why this broke Q18 and empty session follow-ups:
   - `FOLLOWUP_PATTERNS` matches "Why did you conclude that?" and "Why did you say that?".
   - In Q18, `dead_pack_sess = f"deadpack_{uuid.uuid4().hex[:6]}"`.
   - `router_input.has_prior` was False.
   - `router_input.turn_count` was 1.
   - The condition `FOLLOWUP_PATTERNS.search(...) and not router_input.has_prior and router_input.turn_count <= 1`
     evaluated to TRUE.
   - This forced `decision.route = "WORKFLOW"` and `clarification_needed = True` with slot `asset_id`.
c. In `agent_service/app/main.py` lines 417-451:
   Because `decision.clarification_needed` was True, `main.py` immediately returned
   a ClarificationFrame asking "Which well would you like me to analyze?" and PAUSED.
   It NEVER reached line 454 (`if decision.route == "FOLLOW_UP":`), which calls `handle_followup()`.
   Thus, `agent_service/app/routing/followup_handler.py` lines 70-75:
   ```python

       return FollowUpResult(
           ok=False,
           code="ANALYSIS_EXPIRED",
           message="Prior analysis expired or not found. Please ask your diagnostic question again.",
       )
   ```
   was NEVER EXECUTED.
d. Why did `test_boundary_no_prior_analysis` previously pass in pytest?
   `test_boundary_no_prior_analysis` reused the fixed session ID `"sess-empty-fup"`.
   In Redis, `"sess-empty-fup"` had accumulated `turn_count=7` from prior test runs!
   Because `turn_count=7 > 1`, `router_input.turn_count <= 1` evaluated to FALSE in
   that specific test run, masking the bug. On any fresh session or when Redis keys

e. Dead pack vs. Empty session distinction:

     so `has_prior=True`. It routes to `FOLLOW_UP`. `handle_followup` attempts
     `get_pack()` which returns None, returning `ANALYSIS_EXPIRED`.

     conclude that?" is a follow-up inquiry with no prior analysis. Asking "Which well?"
